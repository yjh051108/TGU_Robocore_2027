## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Config file -> Detector | TOML config parsed at construction for threshold parameters |
| Camera frame -> Detector | `cv::Mat` input validated by OpenCV's built-in bounds checking |
| ROI extraction -> image bounds | `get_pattern()` and `detect(Armor&)` manually clip ROI to image bounds |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02-01 | Tampering | Config file (TOML) | accept | Local config file in project directory. Parameters are thresholds (doubles) — tampering affects detection quality, not security. |
| T-03-02-02 | Denial of Service | ROI bounds violation | mitigate | `get_pattern()` clips ROI via `std::max<int>(..., 0)` and `std::min<int>(..., img.cols/rows)`. `detect(Armor&)` checks `boundingBox.x < 0 || boundingBox.y < 0 || ...` before ROI crop. Both bounds-checking patterns from source code are verified present. |
| T-03-02-03 | Information Disclosure | save() pattern files | accept | Low-confidence armor ROIs saved to local `patterns/` dir. No PII in images. Path not user-controllable. |
| T-03-02-04 | Denial of Service | cv::Mat contour processing | accept | `cv::findContours` and `cv::minAreaRect` are standard OpenCV functions. Malformed input is handled by OpenCV's internal guards. No custom memory management. |
</threat_model>
